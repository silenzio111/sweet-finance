本地优先的个人账本

把钱花在哪，
一眼就清楚。

一个以手机体验为中心的本地记账本。收入、支出、储蓄和年度目标各得其所，不把你的账本变成一张无尽的表格。

研发的起点，是对“坚持记账”这件事的重新理解。

许多记账工具把重点放在复杂报表、账户体系或云端同步上，但日常真正让人放弃的，往往是录入动作太重，以及打开应用后看不到与自己有关的答案。SweetFinance 从一个更朴素的问题出发：今天的收入、固定支出、临时消费和正在积累的储蓄，能否在一块不会令人紧张的界面里被看清楚。

因此它没有把“功能越多”当作目标，而是围绕连续使用的节奏设计。精简视图适合快速确认本月状态，明细视图则留给想理解分类和项目的人；年度切换不是为了做形式化的报表，而是让一套账本能够自然地跨过新年、工资调整或生活阶段的变化。

账本不是一张表，而是一组会变化的关系。

在数据模型上，SweetFinance 将收入、支出、储蓄、分类、年度和调整记录分开维护，再在界面层汇总为净结余、储蓄率、支出占比与分类统计。这样做的原因是现实中的记账并不稳定：类别会改名，项目会停用，金额会被修正，使用者也会逐渐形成自己的浏览顺序。把这些变化视为一等需求，比强迫用户适应一张固定表格更可靠。

撤销、重做、调整历史和明确的确认界面也是同一思路的一部分。财务记录的错误通常不是技术错误，而是匆忙录入、误删或记忆改变。应用不假装用户永远不会出错，而是保留能回看和纠正的路径，让账本成为可维护的个人记录，而不是一次写错就令人不敢触碰的档案。

技术选型服务于移动体验与长期可维护性。

界面采用 React 构建，以组件和状态 Hook 拆分账目、分类、视图切换、对话框与操作历史。Vite 负责本地开发与生产构建，使 Web 端保持快速迭代；Tailwind 让间距、字号和不同尺寸屏幕上的布局规则集中在样式层，而不是散落在大量专用页面中。

同一套前端再通过 Capacitor 封装为 Android 应用。选择这种方式并非把手机端当作浏览器的附属品，而是希望数据逻辑、交互和视觉语言保持一致，同时仍能接入原生文件导入导出与 SQLite 存储能力。Web 环境可以使用本地浏览器存储，Android 端则可以把数据落在设备数据库中；两种路径都把数据控制权留在使用者手里。

隐私和备份不是附加功能，而是产品边界。

SweetFinance 不要求注册账户，也不以广告分析为前提。账本默认保存在设备本地，导出、导入和数据库备份都由用户主动发起。这样的边界会牺牲一些“自动同步”的便利，却避免把日常消费、收入和储蓄目标变成另一项被收集、分析和转卖的数据资产。

项目目前适合希望从源码运行、二次开发或自行打包 Android 版本的使用者。安装 Node.js 20 或更高版本后，执行 npm install 和 npm run dev 即可开始开发；完整构建与移动端同步流程写在仓库 README 中。开源并不承诺每个人都要以相同方式记账，它更希望这套工具能够被改造成适合不同生活方式的账本。
